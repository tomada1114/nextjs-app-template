# Smart Commit

**Owns:** turning a working tree into commits on the current branch — what goes in, how
it is grouped, the message, the recovery when the pre-commit hook refuses, and the push
when one is asked for. **Does not own:** opening or updating the pull request
(`create-pr`); shipping an issue end to end (`shipping-issues`); what the hook runs
(`changing-gates`); the order of work that produces a `src/` change (`tdd`).

A user-level skill of the same name may also be installed. Inside this repository,
follow this one: it is the one that knows this hook.

**Invoking this skill is the sign-off for exactly these writes, for this invocation
only:** the commits it makes on the current branch, and — only when the request asked
for a push — pushing that branch to `origin`. Nothing else: no force-push, no amend of a
pushed commit, no other branch, no push of the default branch (AGENTS.md's "Standing
exceptions").

## 1. State first

```bash
git branch --show-current
git status --short
git log --oneline -5
git diff --stat
git diff --cached --stat
```

- **On the default branch:** stop and ask, unless the request plainly wants a direct
  local commit there. `.github/rulesets/main.json` requires a pull request into `main`,
  so such a commit reaches it only through a branch — never push the default branch.
- **Detached HEAD:** stop and ask; a commit there belongs to no branch.
- **A merge or rebase in progress:** the hook runs only part of itself there — see
  [references/pre-commit-hook.md](references/pre-commit-hook.md). At a rebase stop,
  commit the resolution with `git commit` before `git rebase --continue`: `--continue`
  alone commits it through no pre-commit job at all.
- **Something already staged** that you did not stage: it is the requester's. Ask before
  folding it into a group or unstaging it.

## 2. Decide what stays out

The mechanical list — `.env*`, `secrets/**`, a private-key path, a credential pattern —
lives in `scripts/lib/guard/` and `check:staged` refuses it at commit time. Do not
restate it; what this step adds is the judgment no pattern sees:

- A real key or token in an innocently named file — a fixture, a config, a log.
- Personal data in a fixture or a test snapshot.
- Something the requester plainly did not mean to commit: a scratch file, a debug log, a
  build artifact that `.gitignore` happens to miss, an editor's backup.

Judge a secret-shaped path by its name in `git status --short`, never by opening it —
AGENTS.md's "Security and human approval" forbids reading `.env*` or `secrets/**` at
all. Leave such a file unstaged and name it in the report.

## 3. Group

One commit per logical change: a reader of `git log` should be able to revert any one of
them without breaking another. Each is a Conventional Commit,
`<type>(<scope>): <summary>` — English, imperative, lower-case, no trailing period,
under 72 characters. The type is one of the `types:` list in
`.github/workflows/check-pr-title.yml`; read it there. The scope follows recent history
(`git log --format=%s -20`): `skills`, `agents`, `hooks`, `deps`, a zone name.

These always move together, in the same commit:

| Change                      | Moves with                                        | Because                                                                                                                                                        |
| --------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json` dependencies | `pnpm-lock.yaml`, regenerated by `pnpm install`   | A lockfile out of step with its manifest fails `--frozen-lockfile` in CI. **BACKGROUND:** `managing-dependencies`, including the sign-off a new package needs. |
| `.agents/skills/<name>/`    | `.claude/skills/<name>/`, from `pnpm agents:sync` | `agents:check` refuses one tree without the other. **BACKGROUND:** `authoring-skills`.                                                                         |
| A behavior change in `src/` | Its test                                          | `test:related` refuses a test-only commit; a code-only one lands untested behavior. **BACKGROUND:** `tdd`'s "Commit".                                          |

When two logical changes touch the same file, stage hunks with `git add -p <file>` (or
`git apply --cached <patch>` where nothing can answer its prompts) — then read the
`format` row of the recovery table before committing.

## 4. Stage by name and commit

For each group, in dependency order:

```bash
git add <path> <path> ...
git diff --cached --stat
git commit -m "<type>(<scope>): <summary>"
```

- Stage by explicit path. Never `git add .`, `git add -A` or `git commit -a`: each
  sweeps in whatever step 2 meant to leave out.
- Check `git diff --cached --stat` against the group before every commit; it is the last
  look before the hook does its own.
- A longer body goes in a file outside the checkout, passed with `-F <file>`, so the
  shell expands nothing in it.

## 5. When the hook refuses

Nothing was committed; the index still holds the group, with `format`'s rewrites already
re-staged into it. Read which job failed and follow its row in
[references/pre-commit-hook.md](references/pre-commit-hook.md), then rerun the same
`git commit`.

Never `--no-verify` (or `-n`), never `LEFTHOOK=0` or any other way to switch a job off,
never an edit to `lefthook.yml` or a guard to make this commit pass. AGENTS.md's
"Security and human approval" holds the prohibition; a refusal you cannot clear is a
stop, reported with the job's output.

## 6. Push only when asked

```bash
git push -u origin <branch>
```

- Only when the request asked for a push, and only the current branch.
- A rejection as non-fast-forward stops: the remote has commits this checkout lacks.
  Never force-push past it.
- A pull request is `create-pr`'s; push here only when the request stops at the push.

## 7. Report

`git log --oneline origin/<default>..HEAD` (or the commits made, when there is no
upstream), whether anything was pushed and where, and every path left uncommitted with
the reason.
